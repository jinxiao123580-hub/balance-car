# 步进平衡车前进控制参考与当前问题

调研日期：2026-10-29，Asia/Shanghai。本轮只读核对源码、最新CSV及公开参考，未修改固件、参数或烧录。

## 结论

改变目标倾角是步进平衡车采用的前进方法，2°并非通用的充分值或通用上限。但本机最新18:25录制的122行中，模式为3，前后请求和斜坡输出全0，尚不能证明车端实际执行过持续2°。先核对指令、再调角度；不能用别人的角度上限替代本机控制链验证。

## 一手来源对照

| 参考 | 前进控制实现 | 对本机的含义 |
| --- | --- | --- |
| JJRobots B-ROBOT EVO2官方代码 | 遥控油门作为速度目标，速度PI生成目标倾角，直立PD输出累加为电机控制量；转向以差速叠加 | 可借鉴完整控制链，但速度估计、单位、机械/驱动和限幅不同，参数不能直接复制 |
| KTH 2020《Self-balancing robot》附录E | 按住前后时逐步改变角度目标，先向约±2.5°变化，再依据电机控制输出继续小步调整；松开时向零回退 | 更接近用户希望的“按住前后，不要求精确定速”；±2.5°是代码中的分段阈值，不是绝对硬上限 |
| 先前参考的twoWheelBalanceCar | README列TB6612FNG、JGB37-520，并注明只实现静态平衡 | 可参考展示结构，不能当作相同TMC步进硬件上前进已验证的证据 |

B-ROBOT EVO2普通模式MAX_TARGET_ANGLE=14、PRO=26；这些是速度环目标倾角的限制，不是要求始终用14°/26°。当前本机在相对O偏差5～10°逐步退权限，10°撤销手动指令，所以照搬14°不会形成同一控制系统。

本次未找到并核验与STM32F407ZG、BMI270、MKS TMC2209及本机机械结构完全一致的成功项目。未将直流车的PWM、别人的throttle单位或控制增益直接换算成本机STEP Hz。

## 与现有源码的差异

现有源码已经将PD结果经R缩放、加速度限制、过零软化后累加到integratedMotorSpeedCommand。B-ROBOT也采用稳定控制输出累加，因此不能将问题简单归因于“我们缺少积分电机输出”。用户拒绝的是新增前后速度积分，二者不是同一个状态。

当前直接倾角路径为O加手动偏移，手动期间速度/位置环旁路，符合倾角遥控的大方向。其效果仍依赖请求到达、姿态估计、PD符号、轮速余量和实际电机跟随。检索到的主要参考并未证明简单给两轮加固定基础频率一定优于当前结构，不能据此跳过平衡控制。

若电机为200整步/圈且实际1/16细分，本机L=1750Hz约32.8RPM。这个换算仅用于核查追车余量；实际细分及机械条件未确认前，不据此断言转速不足，也不改L/S/B/H。

## 当前CSV与通信证据

[最新CSV](../validation/recordings/ble_tune_log_20261029_182546_662_p28652.csv)122行有效遥测，manualControlMode=3，manualReq1000与manualApplied1000全0，outer authority为1。调O发生变化不等同于发送前后偏移。可能涉及使能、旧进程、按钮或收发路径；仅凭CSV无法唯一归因，短于采样周期的事件也不能完全排除。

源码BT_BAUD=9600。按此CSV重建的遥测帧平均约211字节，4Hz约843字节/秒；8N1理想容量960字节/秒。运动确认等回复还会占用带宽，存在余量不足与延迟风险。这是容量估计，不是通信堵塞导致零请求的定论。

## 建议的下一步

1. 先让车端请求/输出显示非零。按住0.3°时，应看到请求约+0.30°、斜坡输出接近+0.30°，目标角接近O+0.30°；否则先查命令和使能，不改控制增益。
2. 对遥测/命令做带宽预算，降低无关回包或遥测量；先不直接修改蓝牙波特率，避免模块配置与STM32不匹配。
3. 若角度确实被执行，再观察PD→积分STEP频率→编码器净运动。这样才能区分软件输出受限、符号、失步或地面阻力。
4. 用户若仍选择非定速方案，可参考论文的按住渐增倾角/松手回零，结合已确认的轮速输出限制，再评估有限扩大角度范围。本轮不直接放大保护阈值，也不重新加入用户已拒绝的速度积分。
