# 2026-11-06 首次速度闭环档位试验：为什么“移动很小”

数据：[ble_tune_log_20261106_090136_225_p18076.csv](../../recordings/ble_tune_log_20261106_090136_225_p18076.csv)
（180 行，2 Hz，27.0–116.5 s，O=6.00°）。分析脚本：`software/analysis/analyze_fwdback_motion.py`。

## 结论：档位不低，是「有效倾角」低，而且速度反馈信噪比不够

满档（档位 2.0，`manualReq1000=2000`）按了 8 段，数据如下：

| 指标 | 前进 | 后退 |
| --- | ---: | ---: |
| 样本数 | 75 | 34 |
| 有效倾角 `target100−O` 均值 | **+0.64°** | **−0.58°** |
| 倾角范围 | −0.26 ~ +1.00° | −1.00 ~ +0.46° |
| 顶到上限 1.00° 的采样 | 8/75（11%） | 2/34（6%） |
| 实测速度均值（绝对值） | 4.5 counts/50 ms | 5.4 counts/50 ms |
| 净位移速率 | **+20 ~ +30 counts/s** | −10 ~ −25 counts/s |

逐段看净位移（前进）：

| 时间 | 时长 | 位移 | 速率 | 平均倾角 |
| --- | ---: | ---: | ---: | ---: |
| 39.5–44.5 s | 5.0 s | +107 | +21 counts/s | +0.65° |
| 46.5–56.0 s | 9.5 s | +40 | +4 counts/s | +0.72° |
| 75.5–81.5 s | 6.0 s | +191 | +32 counts/s | +0.59° |
| 91.5–95.5 s | 4.0 s | +82 | +21 counts/s | +0.65° |
| 109.5–115.5 s | 6.0 s | +147 | +25 counts/s | +0.66° |

而车端的目标是 `档位2.0 → 5 counts/50ms = 100 counts/s`，实际只有 20~30 counts/s，约 1/4。

三个直接原因：

1. **倾角太小、接近静摩擦阈值。** 平均只有 0.64°，而 10-31 那次开环 1.9° 能把车明显推走。前馈系数
   `0.10×v_ref` 在 v_ref=5 时只给 0.5°，误差项又只占 0.05×5=0.25°。
2. **倾角被速度噪声打散。** 50 ms 速度窗口的噪声约 ±8 counts/50 ms（t=40.0 时 +17.2，t=41.0 时 +2.55），
   比目标 5 还大；误差项把倾角在 0.4~1.0° 之间逐拍来回推（见 39.5–44.5 s 段：0.58→−0.04→1.00→0.62），
   平均推力反而被拉低，轮子来回晃、净位移小。
3. **上限 1.00° 被反复顶到**（11% 采样），说明噪声峰值已经在限制输出，而不是倾角需求真的只有 1°。

## 本轮的参数修正

| 参数 | 旧 | 新 | 理由 |
| --- | ---: | ---: | --- |
| `maxSpeed`（满档速度目标） | 5 counts/50ms | **10 counts/50ms** | 提高信噪比（目标 10 vs 噪声 ±8），也让速度真正够用 |
| `accel` | 10 | **20** | 保持 0→满档约 0.5 s |
| `feedForwardGain` | 0.10 | **0.12** | 满档稳态倾角 1.2°，高于 10-31 观察到的摩擦阈值，但仍远低于开环 2° |
| `speedErrorGain` | 0.05 | **0.02** | 噪声 ±8 时只引入 ±0.16°，不再主导倾角 |
| `limit` | 1.00° | **1.50°** | 给前馈+误差留余量，避免被噪声顶死 |
| 速度反馈 | 原始 | **30 ms 一阶低通** | 减少 50 ms 窗口噪声进入倾角 |

面板同步：档位换算由 `×2.5` 改为 `×5 counts/50ms`，状态栏倾角上限提示改为 1.5°。

## 上车验证顺序

1. 烧新固件（RAM 8112 B / Flash 84436 B），重启面板确认“速度闭环前后就绪”；
2. 档位先用 **2.0**，短按 1 s，看状态栏倾角是否稳定在 **1.1~1.3°**（不再是 0.6 上下乱跳）；
3. 若净位移仍小于 40 counts/s：把 `feedForwardGain` 加到 0.14~0.16（倾角 1.4~1.6°，注意上限 1.5 会截断），
   不要先动 `speedErrorGain`；
4. 若出现明显前倾/后仰收不住，立即把 `feedForwardGain` 退回 0.10、`limit` 退回 1.0°——说明 1.2° 已经超过本车能稳住的范围；
5. 记录新 CSV 后重新跑本报告的三张表，比较净位移速率。
