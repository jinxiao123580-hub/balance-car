# 2026-11-06 前进快、后退慢：定量与排查

数据：[ble_tune_log_20261106_141856_983_p38936.csv](../../recordings/ble_tune_log_20261106_141856_983_p38936.csv)
（152 行，2 Hz）。参数：前馈 0.06、误差 0.05、上限 1.20°、200 ms 净速度、O=6.0°。

## 定量：同等倾角，前进约是后退的 2.2 倍

取每次按住**去掉起步 0.5 s**之后的相邻采样，用位置差算速率：

| 方向 | 样本 | 平均倾角 | 平均速率 | 中位速率 |
| --- | ---: | ---: | ---: | ---: |
| 前进 | 13 | +0.87° | **+85 counts/s** | +80 |
| 后退 | 36 | −0.92° | **−38 counts/s** | −25 |

倾角几乎相同（0.87 vs 0.92），速率差 2.2 倍。这解释了“一边快一边慢”。

稳态窗口（每段后 60%）也能看到同样的规律：前进段 +55~+156 counts/s，后退段 −17~−32 counts/s。

## 两个可能的成因，本质相同

设真实平衡点为 `P_true`，面板平衡点为 `O`，令 `b = O − P_true`。则

- 前进时的有效倾角 = 0.87 + b
- 后退时的有效倾角 = 0.92 − b

若轮子响应近似与有效倾角成正比，代入 85/38 = 2.24 解得 **b ≈ 0.37°**，也就是 O 比真实平衡点高约 0.37°。
按这个估计，把 O 从 6.0 调到 **约 5.6** 会让两个方向接近对称。

`b` 的来源可能是：

1. **IMU/安装角或 O 标定偏高**（最常见，等价于一个固定角度偏置）；
2. **机械不对称**（电池位置导致质心偏移、左右轮/链条阻力不同），效果同样表现为某个方向的“有效倾角”更大。

现有数据无法把这两者分开，因为 CSV 里没有独立的外部倾角。

## 决定性测试（2 分钟，建议先做）

1. 面板把 `X`（位置环）设为 **0**，不要按前后；
2. 车放同一块地面，手扶到接近直立后松开，让它**自由平衡 20~30 s**（会缓慢漂移，属正常）；
3. 记录 CSV，取中段的平均 `pitch`，就是真实平衡点 `P_true`。

判读：

| 结果 | 结论 | 处理 |
| --- | --- | --- |
| `P_true` ≈ 5.6~5.7 | O 标定偏高 | 把 O 改成测出的 `P_true`，重测前后对称性 |
| `P_true` ≈ 6.0 | 平衡点没错 | 属机械不对称，需要在固件里加**方向配平**（前进/后退各一个小的倾角偏置，默认 0） |
| 自由平衡时始终往一个方向跑 | 同一结论，且方向就是“跑”的那一边 | 同上 |

## 如果确认是机械不对称

在 `motion_drive.h` 增加一对常量（例如 `forwardTrim = 0.0f`、`backwardTrim = 0.0f`，单位 deg），
乘在 `v_ref` 的符号上，逐次按 0.1° 调，直到两个方向在同档位下速率接近。这个偏置不参与速度环，
只平移运动倾角，不会改变平衡/驻车行为，回退只需置 0。

## 附带观察（本轮记录）

- 静止段（t>60，无指令）平均 `pitch−O = −0.05°`、`lean = −0.06°`，位置缓慢后退 6 counts/s；
- 7 个真正静止（|速度|<0.5 且 |STEP|<80）采样里 `pitch−O` 中位 +0.06°、最大 +0.96°——
  样本太少，不能直接当作 `P_true` 的证据，所以建议单独做上面的自由平衡测试。
